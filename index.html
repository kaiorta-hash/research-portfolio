MEA-CartPole

A closed-loop brain-computer interface that turns a CartPole game into electrical stimulation of living neurons on a 60-electrode array, then reads their spiking back as moves.

Kai Ortadeveci, Co-LeadFeb 2026 to presentUpdated Oct 2026
Hardware brought up Pipeline audited v2 encoding/decoding designed First live-neuron sessions next

No live-neuron sessions have run yet. Every result on this page comes from simulation or hardware checks, not from neurons learning the task.

The question

Can a culture build a pathway it was never given?

Cortical neurons on an array have improved at Pong (DishBrain, Kagan et al., 2022), and cortical organoids have shown goal-directed learning on CartPole (Robbins et al., 2026). That second result used a high-density array with 26,400 electrodes, which can find circuits that already exist and train them.

Our array has 60 electrodes at 200 µm spacing, about 11 times coarser. Each electrode hears a small cluster of cells, not one neuron. So we ask a different question: can a dissociated culture learn an input-to-output mapping we impose on it, forming a new pathway instead of strengthening one that was already there?

How the loop works

One game step, end to end

  1. GameCartPole reports the pole's angle and angular velocity.
  2. EncodeThe state becomes a stimulation pattern: which electrode, at what pulse rate.
  3. StimulateBiphasic, charge-balanced pulses go into the dish.
  4. RecordAll 60 electrodes are sampled at up to 50 kHz.
  5. DecodeSpikes on the left and right output electrodes pick push-left or push-right.
  6. FeedbackA separate training signal, on its own generator, follows performance.

Python runs the game, encoder and decoder. C# drives the MCS MEA2100-Mini through its SDK. In v2, each game step gets its own 200 ms cycle.

My work

What I built and found

Brought up the hardware

  • Set up the MEA chip and headstage from the system manual and confirmed raw data streaming from all 60 channels.
  • Traced the full signal path, Python to C# to the MCS SDK to the device, and logged where it broke: an interface file never wired into the main program, dummy data in place of electrode data, compile errors, and a hardcoded stimulation waveform.
  • Showed from the hardware manual that the old amplitude encoding (120 to 180 µV) fit inside a single 305 µV DAC step, so amplitude carried no information at all.

Audited the inherited pipeline by running it

I ran the existing encoding and decoding code instead of only reading it, and documented 15 defects. The ones that mattered most:

  • The game state never reached the neurons. Radians were treated as degrees, so stimulation moved between 19.8 and 20.2 Hz instead of 10 to 30 Hz.
  • The loop rewarded itself. Stimulation landed on the same electrodes used to decode the move, so whichever side won once would likely keep winning.
  • There was no real feedback. The reward branch fired every step and the punishment branch could never run.
  • Decoding was off by design. Filter cutoffs were wrong by about 20 times from a bad sampling-rate assumption, and the code counted samples instead of spikes.

Redesigned encoding and decoding (v2)

The rule behind v2: input and output live in separate regions, so a move has to cross the network instead of echoing the stimulus.

Input row: pole angle picks one of 6 electrodes
Output row: 3 left vs 3 right decide the move
The network in between, recorded throughout

Angle sets where the dish is stimulated. Angular velocity sets how fast: a signed pulse rate from 10 to 40 Hz, faster when the pole is falling and slower when it is recovering.

Tested every design choice in simulation first

Before using hardware time, I simulated scripted CartPole policies and toy cultures in Gymnasium, 300 to 1,000 episodes per test, and changed the design where the numbers said to.

49%of steps would get the wrong side if we added a 1° buffer at vertical, hiding left and right exactly when play improves. I had proposed the buffer, then dropped it.
500 → 10steps for a perfect controller forced to hold each decision 200 ms in real time. This is why v2 slows the game to one step per cycle.
42 vs 11steps for a toy culture that only spreads activity, under normal vs mirrored mapping. Learning has to beat each dish's own baseline, not random play.
46 → 0of 50 episodes ending on the cart's position limit once we removed it, so episodes end on the pole, which is the skill we measure.

Designed controls that separate learning from look-alikes

  • Timing-shuffled feedback: the same training signal, the same number of times, at random moments. I narrowed it to shuffle only feedback events, since shuffling the whole log would leave the culture playing blind and the control could never fail.
  • Mirrored mapping in half the dishes, to rule out electrode geometry.
  • Mid-session rule change: reverse the push direction; real learning should drop, then recover.
  • Whole-dish firing logged every minute to track homeostatic drift.

Several of these came from conversations I set up with Cortical Labs and a UC Berkeley neuroscience professor.

Reviving an unpublished model of visual cortex

A computational model, from a 2015 USC PhD dissertation, of how the brain learns to recognize visual features without any labels or teaching signal.

Research AssistantAug 2025 to presentMATLAB, Python, TensorFlow/Keras, Claude Code

Note on disclosure: this work is unpublished and is being prepared for publication with the original author and PI. I can't share results, figures, parameter values or code here, so this section stays at a high level.

The question

How does the brain grow so many different feature detectors?

Neurons in mid-level visual cortex (areas V2 and V4) respond to a huge variety of curves, corners, textures and shapes. How that variety develops without supervision is an open question. The model proposes a simple two-stage mechanism, which works like a hybrid Kohonen self-organizing map with a threshold gate in the first layer.

1. Threshold gateA simulated patch of primary visual cortex (V1) looks at small natural-image patches and passes on only the ones that excite it most strongly.
2. Competitive learningA large population of model V4 cells learns from those patches. Only the most active cells adjust toward each one. No labels, no backpropagation.
The challenge

Three sources, none trustworthy alone

The code had not run in about a decade, the scripts that set each experiment's parameters were lost, and the dissertation, the code and the code's comments disagreed with each other in many places.

My role

What I did

  • Got it running again on modern software and new natural-image datasets without changing its science, keeping the original files for comparison.
  • Traced the math of the entire model from the dissertation into the code, and resolved the places where they disagreed using evidence from archived files.
  • Extended the hybrid learning rule to natural images and tuned the model across a large parameter campaign.
  • Reproduced the dissertation's central claims on new data.
  • Measured the model's computational cost and made its first stage more efficient.
  • Built an AI-assisted research workflow in Claude Code, with approval gates before any change, standardized reports, and every edit checked against the original.

Results will be shared once the work is published.
